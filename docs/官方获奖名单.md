# 官方获奖名单（/admin/official-awards）

对应 Issue：[Web #138](https://github.com/gduf-community/ai-data-competitions-ui/issues/138)、
架构基线 [API #131](https://github.com/gduf-community/competition-Q-A-website/issues/131) 第 6、7 节、
更正撤销 [#134](https://github.com/gduf-community/competition-Q-A-website/issues/134)、
查询导出 [#135](https://github.com/gduf-community/competition-Q-A-website/issues/135)。

Web 只负责页面与 BFF 消费；授权、匹配、事务、文件生成都在 API 侧完成。

## 路由

| 路径 | 归属 |
| --- | --- |
| `/admin/official-awards` | Web #136（赛事入口，本 PR 不实现，只提供导航） |
| `/admin/official-awards/competitions/[competitionId]` | **Web #138（本文档）** |

## 接口契约

```text
GET   /api/admin/official-awards/competitions/{competitionId}?year&level&subTrack&q&cursor&limit
GET   /api/admin/official-awards/competitions/{competitionId}/export?view=award|member&format=csv|xlsx&<同筛选>
PATCH /api/admin/official-awards/{awardId}       { expectedVersion, reason, levelCode, subTrack, teamName, members[], advisors[] }
POST  /api/admin/official-awards/{awardId}/void  { expectedVersion, reason }
```

`{competitionId}` 与 `{awardId}` 都是 **UUID**。BFF 白名单按 UUID 精确匹配，锚定路径、不接受额外子路径：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/competitions/{uuid}` | 列表与汇总 |
| `GET` | `/competitions/{uuid}/export` | 双视图文件流 |
| `PATCH` | `/{uuid}` | 更正事实与成员/老师 |
| `POST` | `/{uuid}/void` | 撤销事实 |

读路径只允许 `GET`（不含 `HEAD`）；写路径只允许对应的一种方法。

## 数据口径

| 指标 | 定义 |
| --- | --- |
| `awardCount` | 奖项数，一奖一行 |
| `memberCount` | 获奖人次，含未核实与匿名 |
| `verifiedMemberCount` | `COUNT(DISTINCT person_id)`，**仅统计 `verification = verified` 且 `personId` 非空**；同名不同人不合并，无身份者不计入 |
| `draftPending` | 导入草稿数，不计入正式事实 |

等级：`levelCode` 为 `special/first/second/third/excellence/other/unclassified`，
`levelRaw` 保留官方原文且可为空；原文不含规范标签时页面提示「原文与规范等级不一致」。

来源枚举：`official` / `registration` / `manual` / `unknown`。

可空字段：`awardYear`、`levelRaw`、`subTrack`、`teamName`，成员的 `grade/college/major`，
老师的 `college`。成员 `personId` 在未核实或匿名时为 `null`。

## 导出

- 视图 `award`（一奖一行）/ `member`（一学生一行），格式 `csv`/`xlsx`
- 范围是当前筛选的**全部**结果，不受分页影响
- 上限 500 项奖 / 5000 人次，超出返回 `413`
- 校验 `Content-Type` 与 `Content-Disposition`；JSON/HTML 一律不落盘
- 支持 `AbortController` 取消
- CSV 单元格以 `= + - @`、Tab、CR 开头的加前缀 `'`，防公式注入（服务端执行）

## 错误处理

| 状态 | 页面表现 |
| --- | --- |
| 401 | 登录失效提示 |
| 403 | 整页「没有权限」，不展示空列表 |
| 404 | 「没有找到这场比赛」 |
| 409 | 版本冲突：保留输入、刷新列表、提示重新核对 |
| 413 | 超出导出上限 |
| 429 | 操作过于频繁 |
| 503 | 审计或服务不可用（审计拒绝时导出不落地） |

## 更正与撤销

- 更正整组替换 `members[]` 与 `advisors[]`，可增删改；未填字段传 `null`
- 必须带 `expectedVersion` 与 `reason`；版本冲突返回 `409`，页面保留编辑内容并重新查询
- 撤销只把 `voided` 置真并记录原因，不做物理删除，历史与审计保留
- 两者都不调用个人奖状接口

## 权限

- 入口按会话中的 `capabilities.canReadOfficialAwards` 显示；该字段由 API 按「当前有效 grant + 赛事范围」下发
- 缺失时按无权限处理（fail-closed），Web 不按角色自行推导
- 按钮可见性由列表返回的 `permissions` 决定，最终授权始终由 API 再次校验

## 隐私与缓存

- 列表与导出均走同源 BFF，`Cache-Control: private, no-store`
- 页面不做 SSR 静态化，具名信息只经浏览器接口获取
- 仓库与本地联调均使用合成数据，不含真实学生或教师资料
