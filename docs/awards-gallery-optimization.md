# 荣誉展示页面优化

## 接入范围

- `/awards`：年度总览，按后台真实年份展示比赛名及证书数量。
- `/awards?year=2026`：指定年份比赛；年份来自数据，不固定为 2026。
- `/awards?year=2026&competition=<id>`：比赛证书，保留等级分组、获奖人及原有证书详情链接。
- 无数据时显示空状态，不补造往年记录、数量或证书图片；后台接口和权限不变。
- 紧凑三级引导只给当前项及可返回的上级显示辅助文字。URL 支持刷新、分享和浏览器前进后退。
- 最新年度成果数字首次进入视野后滚动约 3 秒。减少动态效果设置及不支持 IntersectionObserver 时直接显示最终数字。
- 蓝色比赛卡片保留小幅鼠标磁吸反馈；触摸与减少动态效果模式不启用。
- 公共顶部导航改为白色横栏，小于 960px 使用展开式菜单，保留登录、通知、个人中心和按原角色规则显示的管理入口。
- 全局浅色底改为白色，奖状详情也使用白底；不删除网站原有深色模式。

## 检查记录与限制

- 新增 5 项合成测试：未来年份、同一比赛跨年、不同比赛、证书总数、等级排序、空数据、客户端字段白名单、URL 编码和无效查询降级。
- 已通过上述 5 项测试及 `git diff --check`。本机 Node 24.19.0 的内置 TypeScript 去类型能力用于执行这组纯函数测试，不等价于仓库指定工具链的完整类型检查或测试套件。
- 当前机器未安装项目依赖；pnpm 遇到 Windows 符号链接权限问题，npm 替代安装遇到 registry.npmjs.org DNS 解析失败。
- 因此不能确认完整 ESLint、TypeScript、Next 构建或浏览器视觉验收通过。提交到功能分支用于后续检查，不应直接合并发布。
- 合并前使用仓库指定 Node/pnpm 版本运行 `pnpm install --frozen-lockfile` 和 `pnpm ci`，并在 320、390、768、960、1440px 检查 A/B/C 导航、图片失败、手机菜单、键盘焦点、减少动态效果和登录状态。
- 此次没有改动后台、审核、上传、数据库或学校仓库的 main 分支。

## 隐私与提交材料

- 服务端将审核通过记录映射为字段白名单后才传入交互组件：证书 ID、公开获奖人名称、比赛 ID/名称/年份、奖项等级、缩略图地址。不传用户 ID、创建时间、原图地址或额外返回字段。
- 白名单减少浏览器暴露面，但公开姓名和证书仍由既有审核/公开接口决定，不代替后端的数据公开授权。源代码与测试中不固化真实获奖人、学生记录或证书图片。
- 本次分支新增内容及差异扫描未发现私钥、常见 GitHub/云 Token、JWT、长凭据字面量、本机用户路径、手机号、身份证号。检查范围不包括仓库全历史、第三方依赖或生产配置，不构成“零漏洞”保证。
- 未新增环境文件、凭据文件、数据导出、真实图片或二进制附件，测试使用合成身份与示例资源。
- 本次读取的 CONTRIBUTING、PR 模板与协作指南未要求额外“通行证”或新许可证。继续使用现有 LICENSE，不得把 Token、Cookie、私钥或生产环境配置放进 PR。
- PR 按官方模板记录修改内容、影响范围、验证结果、截图缺口与备注。不覆盖主 README，只补充功能入口与当前状态。
- 桌面/手机脱敏截图、完整 CI、公开/登录/管理员身份的真实交互验收尚未完成，因此先以 Draft PR 交流，不建议直接合并或发布。
