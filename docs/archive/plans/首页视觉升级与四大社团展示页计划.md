# 首页视觉升级与四大社团展示页计划

## 1. 文档定位

本文档用于规划两项前台展示增强工作：

1. 首页视觉与交互升级
2. 新增“学院四大社团”展示页

本计划建立在以下现有文档之上：

- `docs/视觉与交互规范.md`
- `./首页门面化改版方案.md`
- `docs/页面结构与用户流程.md`

本次只输出方案，不直接落代码。

## 2. 需求理解与边界

### 2.1 目标

1. 让首页更有“门面感”，但仍保持学院官方门户，而不是通用营销页。
2. 吸收 `react-bits-main` 中你喜欢的“图示化界面交互逻辑”，重点借鉴其信息组织、悬停反馈与视觉节奏，而不是照搬品牌外观。
3. 增加一面向学生公开访问的“四大社团”展示页，用来承接学院社团生态、赛事支持方向与参与入口。

### 2.2 约束

1. 继续遵守“竞赛平台优先于炫技展示”的项目定位。
2. 不直接在 `react-bits-main` 中做业务开发。
3. 如果采用第三方组件，必须将必要源码复制到当前项目的 `src/` 结构后再裁剪，不允许从 `react-bits-main` 直接 import。
4. 后台 `/admin`、报名链路、审核链路不纳入本轮范围。

## 3. 当前项目现状判断

### 3.1 首页现状

当前首页 `src/app/page.tsx` 已接入：

- `NewNavbar`
- `NewHero`
- `NewStats`
- `NewFeatured`
- `NewHallOfFame`
- `NewCta`

同时，首页仓储 `src/server/repositories/homepage-repository.ts` 已经返回：

- `featuredCompetitions`
- `latestNotices`
- `resourceLibrary`
- `hallOfFameEntries`
- `featuredFaqs`

当前判断需要进一步收紧：

1. `latestNotices` 已经被用于首页快速入口计数，但 `NewNoticeBoard` 区块本体已从首页主流程移出。
2. `resourceLibrary`、`featuredFaqs` 仍停留在仓储层，没有进入首页结构。
3. 首页通知能力当前更适合保留为“导航栏铃铛 + 快速入口计数跳转”，而不是重新展开为首页中段公告区。

说明首页的“内容层”已有基础，当前更缺的是编排、样式统一和表现层升级。

### 3.2 现成可复用组件

当前仓库已经存在可直接复用或延展的展示组件：

- `src/components/marketing/new-notice-board.tsx`
- `src/components/marketing/portal-resource-board.tsx`
- `src/components/marketing/portal-faq.tsx`
- `src/components/motion/spotlight-card.tsx`
- `src/components/motion/marquee.tsx`
- `src/components/motion/fade-in-on-scroll.tsx`
- `src/components/motion/stagger-children.tsx`
- `src/components/ui/glow.tsx`

但需要注意：

1. `portal-resource-board.tsx` 与 `portal-faq.tsx` 仍使用旧版 `slate-*` 硬编码色值和衬线字体方案。
2. 它们与当前 `NewHero`、`NewFeatured` 所在的新首页语义色体系并不一致。

因此首页升级应优先走“重组现有能力 + 选择性吸收 React Bits 交互逻辑”的路线，但不能直接把旧版 `portal-*` 组件原样插回首页。

### 3.3 现有公开页面语义

当前已经存在：

- `/team`：网站团队页
- `/hall-of-fame`：名人堂页

因此“四大社团”页面不应与 `/team` 混用，建议新增独立公开路由：

- `/clubs`

## 4. 总体设计策略

### 4.1 视觉方向

首页建议采用“学院科技门廊”方向：

- 保留学院官方感和可信度
- 首屏允许更强的氛围背景和图示化交互
- 正文区继续使用清晰的栏目化结构
- 动效只集中在前台公开页，且优先服务“找比赛、看通知、看社团”

不建议整站复制截图中的紫黑色产品营销风格。更合适的做法是借用其交互逻辑，转译成学院竞赛语义：

| 图示灵感 | 本项目转译方式 |
|---|---|
| 点阵/网格背景 + 光晕 | 首页首屏使用受控的点阵背景、径向光晕、轻微流动线条 |
| 左文案右演示窗 | 左侧为门户定位与主 CTA，右侧改成“赛事情报窗”而不是代码窗 |
| 首栏初始舒展、滚动后缩小 | 首页导航首栏在首屏保持正常高度，滚动后收缩为紧凑态 |
| 悬停聚焦卡片 | 用于首页快速入口、社团卡片、资料入口卡片 |
| 分层滚动显现 | 用于赛事、通知、社团预览依次入场，不做过度滚动接管 |

### 4.2 第三方仓库使用原则

`react-bits-main` 只作为上游灵感与源码来源，分三档处理：

#### A 档：优先采用

- `SpotlightCard`
- `MagicBento`
- `ChromaGrid`

其中：

- `SpotlightCard` 已有本地实现，优先复用本仓库版本
- `MagicBento` / `ChromaGrid` 更适合承载“四大社团”这种展示型卡片矩阵

#### B 档：可选增强 / 评估后采用

- `Dock`
- `PillNav`
- `LineWaves`
- `ColorBends`
- `TextPressure`
- `ScrollReveal`

这些组件适合用来提炼“首屏氛围感”或“切换导航反馈”，但不建议整包照搬。

补充说明：

- `Dock` 的 macOS 风格放大反馈不列为阶段 B 必做项，只作为桌面端可选增强。
- 社团页与首页都应先验证基础信息是否值得展示，再决定是否引入更强交互。

#### C 档：当前暂缓

- `Orb`
- `Particles`
- `GridMotion`
- `ScrollStack`
- `InfiniteMenu`

原因：

1. 依赖 `ogl`、`three`、`lenis`、`gsap` 等较重运行时。
2. 更容易把首页带向“炫技站”而非“学院门户”。
3. 对移动端和首屏性能压力更大。

## 5. 首页改造方案

### 5.1 首页目标形态

首页建议调整为以下顺序：

1. 顶部导航
2. 首屏 Hero + 赛事情报窗
3. 快速入口条
4. 重点赛事区
5. 资料下载与 FAQ 区
6. 四大社团预览区
7. 名人堂区
8. 收尾 CTA 与页脚

补充说明：

- 首页通知入口仅保留为导航栏铃铛与 `NewStats` 快速入口卡，不再恢复首页中段“通知公告区”。
- 首页导航可参考第三方仓库的首栏逻辑：首屏阶段保持正常高度与较宽留白，滚动后再收缩为紧凑态。

### 5.2 首屏改造重点

当前 `NewHero` 已具备“左文案 + 右重点赛事卡”骨架，可以继续增量演化，不建议推倒重做。

建议改造点：

1. 背景层加入点阵网格、柔和光晕、轻量流线氛围。
2. 右侧卡片从“单赛事卡”升级为“赛事情报窗”：
   - 主卡：本周重点赛事
   - 次卡：最新公告摘要
   - 资料/指南快捷入口
3. 快速入口条由当前偏统计的 `NewStats` 转成更强交互的门户入口卡。
4. `NewNavbar` 在首页首屏阶段保持正常高度，页面下滚后切换为紧凑导航态。

### 5.3 首页组件落位建议

优先在现有结构中增量调整，不先做无意义重命名：

- `src/app/page.tsx`
  - 重新编排首页模块顺序
  - 接入 `resourceLibrary`、`featuredFaqs`
- `src/components/marketing/new-hero.tsx`
  - 扩展为更完整的首屏展示层
- `src/components/marketing/new-navbar.tsx`
  - 支持“首屏正常态 / 滚动紧凑态”两段式导航
- `src/components/marketing/new-stats.tsx`
  - 改造成“快速入口条”
- `src/components/marketing/new-resource-board.tsx`
  - 新增，承接资料区，并沿用新首页语义色体系
- `src/components/marketing/new-faq.tsx`
  - 新增，承接 FAQ 区，并沿用新首页语义色体系
- `src/components/marketing/home-club-preview.tsx`
  - 新增，用于首页承接四大社团预览

不建议阶段 A 直接使用旧版 `portal-resource-board.tsx` 与 `portal-faq.tsx` 原样上首页。若短期复用旧组件，也需要先完成一轮样式适配。

### 5.4 React Bits 映射建议

| 首页区域 | 建议做法 | 来源 |
|---|---|---|
| Hero 背景 | 先用本地 `Glow` + CSS 点阵网格实现；如仍不够，再评估裁剪 `LineWaves` | 本地 + React Bits 灵感 |
| 快速入口条 | 默认使用普通卡片和本地 `SpotlightCard`；如桌面端实测效果确实更好，再评估 `Dock` | 本地优先，`Dock` 可选 |
| 赛事/资料卡片 | 优先用本地 `SpotlightCard` 增强 hover 反馈 | 本地 `spotlight-card` |
| 社团预览四宫格 | 参考 `MagicBento` 或 `ChromaGrid` 的视觉组织逻辑 | `MagicBento` / `ChromaGrid` |

## 6. 四大社团展示页方案

### 6.1 路由建议

新增独立公开页：

- `/clubs`

首页新增“社团生态”入口，导航也建议补充：

- 顶部导航加入 `四大社团`
- 首页中段新增“四大社团预览区”

### 6.2 页面定位

这个页面的角色不是网站团队页，也不是招新海报页，而是：

**学院竞赛生态展示页**

它应回答三个问题：

1. 学院有哪些核心学生社团
2. 每个社团分别支持哪些竞赛方向
3. 学生应该从哪里加入、关注或参与活动

### 6.3 建议信息结构

建议页面顺序如下：

1. 页面首屏
   - 标题：学院四大社团
   - 副标题：社团定位与竞赛支持方向
   - 主 CTA：查看社团方向
   - 次 CTA：查看近期比赛
2. 社团总览区
   - 4 张主卡片
   - 每张卡片展示名称、定位、代表方向、年度活动
3. 社团详情切换区
   - 展示每个社团的深度介绍
   - 第一版优先使用锚点、tabs 或普通分段导航
4. 社团支持的竞赛方向矩阵
   - 例如建模、程序设计、电子设计、机器人、创新创业等
5. 年度活动 / 成果展示
   - 活动海报、训练营、赛事成果、合作老师
6. 加入方式与咨询入口
   - 招新时间
   - 联系方式
   - 相关链接

### 6.4 组件落位建议

- `src/app/clubs/page.tsx`
  - 页面编排入口
- `src/components/marketing/clubs-hero.tsx`
  - 社团页首屏
- `src/components/marketing/clubs-overview.tsx`
  - 四社团总览区
- `src/components/marketing/clubs-detail-switcher.tsx`
  - 社团详情切换区
- `src/components/marketing/clubs-activity-gallery.tsx`
  - 年度活动 / 成果展示区
- `src/components/marketing/clubs-join-guide.tsx`
  - 加入方式与咨询入口

### 6.5 数据建议

第一阶段不引入后台管理，采用静态内容源即可。建议新增独立内容文件，而不是继续膨胀 `src/lib/mock-data.ts`：

- `src/lib/data/clubs.ts`

建议结构至少包含：

- `id`
- `name`
- `shortName`
- `slogan`
- `description`
- `focusAreas`
- `flagshipActivities`
- `relatedCompetitions`
- `advisorOrContact`
- `joinGuide`
- `coverImage`
- `themeColor`

后续如果要做后台维护，再把这一层抽到数据库或后台配置页。

### 6.6 React Bits 映射建议

| 社团页区域 | 建议做法 | 来源 |
|---|---|---|
| 四社团主卡 | 第一版先用 4 张清晰卡片 + “查看全部”入口验证信息价值；后续再评估 `MagicBento` | 本地优先，`MagicBento` 作为增强 |
| 社团切换导航 | 第一版先用普通 tabs 或锚点；桌面端再评估 `Dock` 或 `PillNav` | 本地优先，`Dock` / `PillNav` 可选 |
| 社团人物或活动卡 | 可参考 `ChromaGrid` 的聚焦方式，但改写为学院内容卡 | `ChromaGrid` |
| 活动图集 | 如确有图片素材，可参考 `Masonry` 或 `Carousel` | `Masonry` / `Carousel` |

## 7. 分阶段实施计划

推荐执行顺序：

`A → C → B → D`

### 阶段 A：首页编排补全

目标：先把首页现有数据和现有组件补齐到“完整门户”。

工作项：

1. `page.tsx` 接入资料、FAQ 区块
2. 调整首页模块顺序
3. 将 `NewStats` 改成更明确的门户快速入口
4. 先统一资料区、FAQ 区的色彩系统与字体语言，再进入首页
5. 首页加入“四大社团预览区”的简版占位块

验收前置：

1. `react-bits-main` 加入 `tsconfig.json` 的 `exclude`
2. 首页不直接混用新旧两套展示语言

验收点：

1. 首页一屏内能看到比赛主入口和至少一个社团入口
2. 资料、FAQ 不再只停留在仓储层
3. 首页结构比当前更完整，但不新增重依赖
4. 资料区与 FAQ 区不再出现明显割裂的旧版 `slate-*` 视觉语言

### 阶段 C：四大社团页上线

目标：完成 `/clubs` 静态展示首版。

工作项：

1. 新增路由和页面组件
2. 录入四大社团静态内容数据到 `src/lib/data/clubs.ts`
3. 首页接入社团预览入口
4. 导航加入 `四大社团`

验收点：

1. `/clubs` 页面结构完整
2. 首页和导航都能进入该页
3. 页面能明确区分四个社团的方向与活动

### 阶段 B：首屏视觉增强

目标：把你喜欢的“图示界面交互逻辑”落到首页首屏。

工作项：

1. 增加点阵背景、受控光晕、卡片聚焦反馈
2. 右侧“重点赛事卡”升级为“赛事情报窗”
3. `NewNavbar` 增加“首屏正常态 → 滚动紧凑态”的公开页首栏过渡
4. 桌面端仅在实测收益明确时，评估是否加入轻量 `Dock` 风格交互

验收点：

1. 首屏观感明显增强
2. 仍能第一时间看懂平台职责
3. 移动端不因为动效而降低可读性
4. 未因增强动效而破坏首页性能预算
5. 导航缩放过渡不影响铃铛、登录入口和主 CTA 的可点击性

### 阶段 D：React Bits 选择性迁入

目标：只为已经验证有效的区块引入必要第三方组件源码。

工作项：

1. 先从低风险组件开始
2. 对迁入代码做中文化、Tailwind 主题化、业务语义化裁剪
3. 验证首屏性能和移动端兼容

验收点：

1. 当前项目不依赖 `react-bits-main` 运行
2. 被迁入组件已经过裁剪，不保留 demo 语义
3. Lighthouse 或本地观感无明显卡顿

### 7.1 性能预算

为避免“好看但慢”，阶段 B / D 统一采用以下预算作为验收参考：

1. 首页首屏 LCP 目标：`< 2s`
2. 首屏新增客户端 JS 预算：`< 200KB`
3. 首屏主内容必须在关闭动画后仍保持完整可读
4. 移动端不得因为背景动效导致明显掉帧或点击延迟

说明：

- 预算用于约束动效增强，不要求在本轮文档里给出最终实测值。
- 一旦某个第三方组件引入后明显突破预算，应回退到更轻的本地实现。

## 8. 风险与规避

### 8.1 视觉跑偏风险

风险：

- 容易做成“炫酷组件展示站”

规避：

- 只允许首屏和社团展示区强化视觉
- 赛事、通知、资料区继续以信息可读性优先

### 8.2 依赖膨胀风险

风险：

- 直接引入 `ogl`、`three`、`lenis`、`gsap` 可能扩大构建和维护成本

规避：

- 第一批只用本仓库已有能力
- 第三方组件采用“逐个迁入、逐个验收”而不是一次性引包
- 参考仓库 `react-bits-main` 保留在根目录时，应同步加入 `tsconfig.json` 的 `exclude`

### 8.3 页面语义混淆风险

风险：

- `/team`、`/hall-of-fame`、`/clubs` 容易混成同类展示页

规避：

- `/team` 只讲网站运营团队
- `/hall-of-fame` 只讲获奖学生与经验内容
- `/clubs` 只讲学院社团生态与参与方向

## 9. 结论

建议采用“先补齐首页内容层，再上线四大社团页，再增强首屏视觉，最后再做选择性第三方迁入”的顺序推进。

本轮最重要的判断是：

1. 首页不需要推倒重写，现有仓储和展示组件已经够用。
