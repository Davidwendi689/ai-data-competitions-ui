我的判断：你首页图片压力大的核心风险有三个。

第一，首页可能直接用了原图或大图。第二，图片卡片太多，首屏和首屏外同时抢带宽。第三，Next Image 的 `sizes`、`loading`、`width/height`、缓存策略可能没系统配置。

## 1. 大家的通用结论：不要全站无脑 lazy

很多人一看到图片多，就直接全部 `loading="lazy"`。这其实不是最优解。web.dev 的分析结论是：懒加载能减少初始图片字节，但如果把首屏/LCP 图也 lazy 掉，会拖慢 LCP；更合理的是**首屏内关键图尽早加载，首屏外图片大量 lazy**。([web.dev][2])

web.dev 后续的实验修正也说明，避免 lazy-load 首屏图，同时 lazy-load 首屏外图片，可以同时获得较少图片字节和更好的 LCP。([web.dev][2])

所以你首页应该这样定规则：

```txt
Hero 主图 / 首屏核心图：不 lazy，必要时 fetchPriority="high"
首屏卡片前 4~8 张：正常加载，不要全都 high
首屏外卡片图：loading="lazy"
列表后续页：滚动到附近再请求数据
```

## 2. Next.js 项目最该先补的是 Image 组件规范

Next 官方文档明确说，`next/image` 是对 `<img>` 的扩展，用于自动图片优化。它要求 `width` 和 `height` 或 `fill`，这些信息可帮助浏览器提前保留比例，避免加载时布局跳动。([Next.js][3])

你首页所有图片组件应该统一封装，不要到处手写 `<img>`：

```tsx
import Image from "next/image";

type HomeImageProps = {
  src: string;
  alt: string;
  priority?: boolean;
  className?: string;
};

export function HomeImage({
  src,
  alt,
  priority = false,
  className,
}: HomeImageProps) {
  return (
    <Image
      src={src}
      alt={alt}
      width={640}
      height={360}
      loading={priority ? "eager" : "lazy"}
      fetchPriority={priority ? "high" : "auto"}
      sizes="(max-width: 640px) 90vw, (max-width: 1024px) 45vw, 320px"
      className={className}
      style={{
        width: "100%",
        height: "100%",
        objectFit: "cover",
      }}
    />
  );
}
```

这里最关键的是 `sizes`。Next 文档特别提醒：如果响应式图片缺少 `sizes`，浏览器会默认假设图片宽度接近 `100vw`，从而可能下载过大的图片。([Next.js][3])

首页卡片里这样用：

```tsx
<HomeImage
  src={work.thumbnailUrl}
  alt={work.title}
/>
```

Hero 图才这样：

```tsx
<HomeImage
  src="/images/home-hero.webp"
  alt="首页主视觉"
  priority
/>
```

不要所有图片都 `priority`，Next 16 里 `priority` 已经被 `preload` 取代，官方也建议多数情况下使用 `loading="eager"` 或 `fetchPriority="high"`，且不要和多个候选 LCP 图混用。([Next.js][3])

## 3. 首页必须改成“缩略图字段”，不要直接用原图 URL

你的首页接口应该只返回首页需要的字段：

```ts
type HomeWorkItem = {
  id: string;
  title: string;
  summary: string;
  thumbnailUrl: string;
  width: number;
  height: number;
};
```

不要返回：

```ts
{
  originalImageUrl,
  largeImageUrl,
  markdown,
  fullContent,
  allImages,
  authorProfile,
  logs
}
```

首页数据应该长这样：

```json
{
  "items": [
    {
      "id": "xxx",
      "title": "xxx",
      "summary": "xxx",
      "thumbnailUrl": "https://cdn.example.com/images/thumb/xxx.webp",
      "width": 640,
      "height": 360
    }
  ],
  "nextCursor": "xxx"
}
```

推荐规格：

```txt
首页卡片图：640×360，WebP，50–120KB
首页头像：160×160，WebP，10–40KB
首页横幅图：1280×720，WebP，150–350KB
详情页图：1920 边界以内，WebP，500–900KB
```

MDN 也明确推荐 WebP/AVIF 这类格式，因为它们通常比 PNG、JPEG、GIF 表现更好；其中 SVG 适合需要任意缩放的矢量图。([MDN Web Docs][4])

## 5. Next 配置也要补

你是 Next 16，`next/image` 的配置要更严格。官方文档里提到，`remotePatterns` 应当限定外部图片来源，否则不应泛放；`domains` 已经不推荐，Next 14 以后更推荐 `remotePatterns`。([Next.js][3])

建议 `next.config.ts`：

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    formats: ["image/webp"],
    qualities: [60, 70, 75, 80],
    minimumCacheTTL: 60 * 60 * 24 * 30,
    remotePatterns: [
      {
        protocol: "https",
        hostname: "你的对象存储域名",
        pathname: "/**",
      },
    ],
  },
};

export default nextConfig;
```

Next 文档说明，默认图片格式是 WebP；AVIF 能更小，但首次编码通常更慢，且多格式会增加缓存存储成本，所以你第一版用 WebP 更稳。([Next.js][3])

缓存方面，Next 的 `minimumCacheTTL` 可以设置优化后图片的缓存时间；官方也指出静态图片导入可以通过内容 hash 和 `immutable` 缓存实现长期缓存。([Next.js][3])

## 6. 首页作品墙需要限制渲染数量

图片卡崩很多时候不是单张图问题，而是首页一次性渲染太多卡片。

建议：

```txt
首页首批：6 或 8 条
点击/滚动加载：每次 8 条
最大预渲染：不要超过 16 条
移动端首批：4 条
```

示例：

```tsx
const PAGE_SIZE = 8;

export async function getHomeWorks(cursor?: string) {
  const res = await fetch(`/api/home/works?limit=${PAGE_SIZE}&cursor=${cursor ?? ""}`);
  return res.json();
}
```

服务端接口：

```ts
export async function GET(req: Request) {
  const { searchParams } = new URL(req.url);

  const limit = Math.min(Number(searchParams.get("limit") ?? 8), 12);
  const cursor = searchParams.get("cursor");

  const works = await db.query.works.findMany({
    columns: {
      id: true,
      title: true,
      summary: true,
      imageThumbUrl: true,
      imageWidth: true,
      imageHeight: true,
      createdAt: true,
    },
    limit,
    orderBy: (works, { desc }) => [desc(works.createdAt)],
    where: cursor
      ? (works, { lt }) => lt(works.createdAt, new Date(cursor))
      : undefined,
  });

  return Response.json({
    items: works,
    nextCursor: works.at(-1)?.createdAt ?? null,
  });
}
```

## 7. 你首页可以直接按这个改造顺序来

第一阶段，最快见效：

```txt
1. 首页接口只返回 thumbnailUrl
2. 首页首屏限制 6–8 张图
3. 全部首页图片换成统一 HomeImage 组件
4. 非首屏图片 lazy
5. 每张图必须有 width/height 或固定 aspect-ratio
```

## 8. 我对你这个项目的具体结论

你这个竞赛问答平台首页，图片优化不应该做成“用户上传时前端压一下就完了”。更稳的工程方案是：

```txt
上传端：限制原图大小 + sharp 生成多规格
存储端：S3/对象存储保存 thumb、medium、large
接口端：首页只返回 thumb
前端端：Next Image + sizes + width/height + 首屏图 eager
渲染端：首批 6–8 张，后续分页/懒加载
缓存端：WebP + 长缓存 + hash 文件名
```

最优先改这三处：

```txt
首页不用原图
首页图片组件统一改成 next/image
首页首屏不要超过 8 张图
```
