# 管理台使用手册

最后核对：2026-10-04（源码操作边界）。本轮未执行后台/生产操作，入口和限制见[模块目录](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/modules/README.md)。

## 1. 适用范围

本文面向当前仓库已落地的管理台功能，重点覆盖：

- 后台首页与数据看板
- 比赛、报名、通知、用户管理
- 名人堂、经验文章、奖状审核
- 社团管理员绑定与社团内容审核
- 安全中心与 SQL 查询台

如果页面能力与本文描述不一致，以现行路由和实际权限控制为准。

## 2. 如何进入管理台

1. 使用有权限的账号登录。
2. 从左侧导航进入 `/admin`。
3. 根据角色看到不同菜单组。

当前侧边栏菜单分组为：

- 总览
  - 后台首页
  - 官网首页
  - SQL 查询台
- 数据看板
  - 看板总览
  - 赛事分析
  - 转化漏斗
  - 用户分析
  - 通知分析
  - 风险预警
- 业务管理
  - 比赛管理
  - 报名审核
  - 通知管理
  - 用户管理
  - 赛程安排
  - 名人堂管理
  - 社团管理
  - 社团内容审核
  - 经验文章审核
  - 奖状审核
- 安全中心
  - 事件列表
  - 告警中心
  - 动作执行
  - 态势感知

## 3. 角色与可见范围

- `super_admin`
  - 拥有完整后台能力，可见名人堂管理、经验文章审核和安全中心。
- `business_admin`
  - 负责业务管理并可读取分析页面；不因此自动获得安全中心、用户权限或受限内容管理能力。
- `competition_admin`
  - 在授权比赛作用域内处理比赛与报名数据。
- `analytics_viewer`
  - 主要用于查看数据看板和分析结果。
- `security_admin`
  - 负责安全中心写操作，并可只读用户管理、执行用户删除；不能管理用户角色。
- `temporary_admin`
  - 临时管理权限，按到期时间自动失效。
- `supervisor`
  - 可读取分析、业务和受限内容管理页面，但不能执行写操作。
- `club_admin`
  - 社团作用域角色，从 `/me/clubs` 管理被授权社团的内容，不作为平台后台主角色。

说明：

- 安全中心菜单仅在具备相应权限时显示。
- 当前侧边栏还会对部分页面做更细的显隐控制，例如名人堂管理、经验文章审核只对具备受限内容读取能力的角色开放。
- `/admin/clubs` 和单个社团管理页仅允许 `super_admin` / 有效 `temporary_admin`；`/admin/clubs/reviews` 允许这两类角色和 `business_admin`。

## 4. 常用工作流

### 4.1 比赛运营

1. 进入 `比赛管理` 新建或编辑比赛。
2. 配置状态、时间线、CTA、说明文案等信息。
3. 在 `通知管理` 中发布全站或比赛通知。
4. 到 `官网首页` 或具体比赛详情页确认展示效果。

注意：

- 当前项目的比赛下线/删除语义应优先按“归档、隐藏、状态切换”理解，不应继续在文档里写成直接硬删。

### 4.2 报名审核

1. 进入 `报名审核`。
2. 按比赛或状态查看待处理记录。
3. 按当前状态和比赛权限处理记录；导出须选择单个比赛，当前最多500条submitted/approved去重记录，列和权限边界见[导出约束](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/报名表数据模型与导出约束.md)。
4. 审核结果由个人中心和后续业务流程承接。

### 4.3 数据分析

1. 进入 `后台首页` 先看整体业务指标。
2. 根据场景进入赛事分析、用户分析、通知分析或风险预警。
3. 如果需要自定义查询，再进入 `SQL 查询台`。

注意：

- SQL 查询台接收结构化查询，按角色/字段白名单用安全数据加载器计算；不是自由SQL执行器。见[现行白名单](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/数据库表字段映射_查询白名单标注版.md)。

### 4.4 成果与人物维护

1. 在 `奖状审核` 中处理学生上传的奖状，决定是否通过以及是否展示到首页作品墙。
2. 在 `经验文章审核` 中处理发布申请、驳回或下线。
3. 在 `名人堂管理` 中发送邀请、审核资料、维护展示顺序和状态。

### 4.5 安全处置

1. 在 `事件列表` 查看异常记录。
2. 在 `告警中心` 处理需确认、忽略或解决的告警。
3. 在 `动作执行` 中执行已实现的 `allow_ip + ip` 放行和回滚。封禁、限速等其他执行器返回501，不能作为已生效处置记录。
4. 在 `态势感知` 中查看地图、风险分布和访问态势。

### 4.6 社团管理

1. 在 `社团管理` 中查看固定社团并进入单个社团管理页。
2. 由具备授权能力的管理员按已注册用户邮箱绑定，按用户ID解绑社团管理员；绑定结果写入统一的 `role_assignment` 社团作用域。
3. 社团管理员在个人中心维护社团内容并提交审核。
4. 平台审核人员执行通过、驳回或强制下线；归档仅超级管理员/有效临时管理员，且当前状态须为offline/rejected。

注意：

- 2026-09-27产品改版目标为取消审核、统一后台和封面必传，尚未落地；本节描述当前旧流程，后续开发按[最新目标](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/社团权限设计.md)执行。
- 当前社团基础资料来自 `src/lib/data/clubs.ts`，管理台不提供任意新增、删除社团能力。
- 社团管理员只能操作被授权的社团，前端菜单显隐不能替代服务端作用域校验。

## 5. 当前页面现状说明

- `/admin/schedule`
  - 当前是简版赛程时间线页，适合查看比赛节点，不是完整日历排班系统。
- 问答治理
  - 当前已有公开问答页面与数据层，但后台独立治理入口并未纳入现行侧边栏主导航。
- 网站团队资料
  - 当前 ` /team ` 页面内容仍由代码内数据维护，不是后台配置页。

## 6. 日常使用建议

- 先从 `后台首页` 看整体负载，再进入具体业务页处理。
- 每次涉及报名导出、奖状展示、名人堂公开展示时，都要确认当前状态和公开范围。
- 每次涉及数据库结构、字段或脚本执行时，先看：
  - [服务器迁移说明](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/服务器迁移说明.md)
