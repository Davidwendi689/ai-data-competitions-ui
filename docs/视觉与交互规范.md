# 视觉与交互规范

源码核对：2026-10-15。当前产品是学院竞赛管理与问答平台。页面以比赛信息、报名、审核结果和内容沉淀为中心；本规范记录持续改进目标，不表示所有设计已实现。页面入口见[页面与流程](./页面结构与用户流程.md)，实际验证见[测试与验收](./测试与验收.md)。

| 页面 | 优先呈现 |
| --- | --- |
| 首页/比赛 | 比赛名称、时间、状态及明确的官网/校内报名入口 |
| 报名/个人中心 | 分组字段、必填与错误、提交进度、审核原因、记录跟踪 |
| 问答/经验 | 可读内容、分页、树形回复与当前 API 返回的操作能力 |
| 管理/安全/固定分析 | 紧凑表格、筛选、详情和稳定操作位置，明确查询/导出范围；SQL 查询台已删除 |

2026-10-23 起，网站统一使用 [GDUF Community 图标](../public/gduf-community-icon-256.png)。门户导航、页脚、认证页和管理台复用 [Logo](../src/components/logo.tsx)；浏览器标签页、快捷方式与 Apple 触控图标由[根布局](../src/app/layout.tsx)统一配置，深浅色主题使用同一张原图。`public/favicon.png` 和 `public/favicon-dark.png` 保留兼容路径，内容与原图一致。

## 交互约定

- 复用现有主题变量、字体、间距、状态标签和基础组件，保持深浅色一致；状态文案与 API 枚举一致。
- 官网报名、填写校内资料、查看微信推文是不同动作，按钮应说清目的。
- 加载、空数据、拒绝和故障分别呈现；失败保留输入并提供可操作重试，不把错误显示成空列表。
- 提交中阻止重复操作；撤回、驳回、取消、删除等操作的确认、原因和失败恢复按具体组件维护，逐入口验收，最终结果由 API 校验。
- 优先语义元素、键盘操作、焦点顺序、标签和替代文本；移动端表单、弹窗与主要 CTA 不能溢出。
- 动效服务信息层级，兼顾 `prefers-reduced-motion`，不阻塞表单和审核。

搜索与分页沿 URL 和[搜索协议](./搜索协议.md)，完整数组与当前样本的范围应清楚呈现。社团保存/发布区分草稿、更新公开内容和下线后重发，上传中显示阻塞原因；409 冲突保留正文供核对，不以成功 Toast 替代真实响应。图片异常保留标题/说明和重试，不能用占位封面通过保存验证。
