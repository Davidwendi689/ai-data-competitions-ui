# 组件选型与分层策略

本文描述完整平台产品与 Web 体验。物理拆分后，页面/组件/SSR/BFF 与浏览器配置归[唯一 Web](https://github.com/gduf-community/ai-data-competitions-ui)，本仓只保留可信 API；职责与证据见[运行拆分](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/Web与API运行拆分.md)。

最后更新：2026-09-14

## 1. 总体原则

现行挂载与跨页能力见[前端底座](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/modules/前端底座.md)，各业务组件入口见[模块目录](https://github.com/gduf-community/competition-Q-A-website/blob/d9a789baed9f45ce033f97da5c627eb4cbcc8dee/docs/modules/README.md)；目录中有组件不表示页面已经使用它。

组件按“基础控件 → 跨页能力 → 领域业务 → 页面组合”分层。优先修改现有组件，只有出现清晰复用点时才新增抽象。

```text
Radix UI / shadcn/ui
        ↓
shared / forms / motion
        ↓
competitions / profile / questions / clubs / admin / security
        ↓
src/app 页面与布局
```

## 2. 当前目录职责

| 目录 | 职责 |
|:---|:---|
| `src/components/ui` | shadcn/ui 与项目基础视觉原语，不放业务数据请求 |
| `src/components/shared` | 上传、空状态、页面标题、通用内容渲染等跨领域能力 |
| `src/components/forms` | 富文本和通用表单字段 |
| `src/components/marketing` | 首页和公开门户展示区块 |
| `src/components/motion` | 轻量入场、计数、跑马灯等公开端动效 |
| `src/components/competitions` | 比赛详情、状态、筛选和报名组件 |
| `src/components/profile` | 个人中心、成果、经验和公开资料组件 |
| `src/components/questions` | 问题、回答、评论和 Markdown 展示 |
| `src/components/clubs` | 社团公开页面组件 |
| `src/components/clubs-admin` | 社团管理员内容编辑与管理组件 |
| `src/components/admin` | 管理台表格、审核弹窗、分析和 SQL 查询台 |
| `src/components/security` | 安全事件、告警、动作和态势感知组件 |
| `src/components/notifications` | 通知铃铛、弹窗和已读同步 |

## 3. 现行组件栈

- 基础交互：Radix UI + shadcn/ui。
- 图标：`lucide-react`。
- 表单：React Hook Form + Zod。
- 表格：TanStack Table。
- 通知：Sonner。
- 图表：Recharts；地图和安全态势专用图表可使用 ECharts。
- 拖拽：已安装的 dnd-kit 依赖。
- 动效：Framer Motion，仅在确有展示或反馈价值时使用。
- 富文本：现有 `rich-text-editor`、服务端清洗和存储 key 链路。
- 图片：现有直接上传、懒加载、压缩和图片变体链路。

## 4. 页面使用边界

### 公开门户

- 允许 Hero、统计、FAQ、CTA、奖状墙和社团展示使用轻量视觉增强。
- 首屏业务信息、主要入口和可访问性优先于装饰效果。

### 表单与个人中心

- 复用现有表单字段、上传组件、状态徽章和时间线。
- 不在客户端单独复制服务端权限或状态机规则。

### 管理台与安全中心

- 使用 Card、Table、Dialog、Drawer、Tabs、Select 等稳定控件。
- 不引入营销化动画；危险操作必须有明确反馈，并由服务端再次授权。
- SQL 查询、导出、上传和安全动作继续使用各自已有的白名单、清洗、限流和审计机制。

## 5. 新增组件判断

新增前依次判断：

1. `src/components/ui` 或现有领域目录是否已有可复用组件；
2. 一个现有类型或函数是否足以解决问题；
3. 是否至少有两个真实调用方，或该组件是否明显独立且复杂；
4. 是否会引入第二套交互、主题或表单状态体系。

没有实际收益时，不为“未来扩展”增加包装组件、新类型或新目录。

## 6. 当前后置项

### 已落地公共出口

- JSON 请求使用 `src/lib/http-client.ts` 的 `requestJSON`，沿用同源 CSRF；失败抛带 status 的错误，取消信号透传，空响应显式声明。业务决定反馈与重试，不在基础函数里弹 toast 或自动重试写入。
- 比赛和通知完整列表使用 `useJSONResource`，解析函数置于组件外保持稳定；换资源/卸载会取消旧请求。写操作仍留在业务页。
- `AdminDataTable` 的 loading/error/onRetry、toolbar、getRowId 可按需组合。完整列表传 data；远程分页同时传 pagination、rowCount、onPaginationChange，搜索也必须由远程消费者处理。远程模式禁用页内排序。
- 比赛编辑状态、默认值与请求转换归 `CompetitionEditor`，父页负责详情请求及成功后刷新；报名草稿恢复统一完整 RHF 值，避免数组残留。

- 社团、经验管理操作已使用相同 `requestJSON` 错误/CSRF 出口；组件业务反馈仍在本域。
- 共享 DTO 从 `lib/contracts` 导入，基础业务类型从 `lib/types` 导入；`mock-data` 只提供演示值。客户端不能直接/经中间模块依赖服务端实现，CI 检查此边界。
- 新板块沿现有目录增加领域组件和明确契约，按需组合列表/请求/表单；导航在现有能力元信息处接入。新增内容类型必须显式更新本域验证、展示映射和 SQL，不引入运行时插件注册中心。

### 后置组件

- `/admin/schedule` 仍使用简版时间线；FullCalendar 未安装，也不是当前既有能力。
- Plate、Tremor、Origin UI、Magic UI、react-dropzone 均不是当前依赖，不应在文档中写成已落地组件。
- 新的重型编辑器、图表套件或完整 UI 库必须先有明确需求和迁移收益。
