## 两仓如何划分

Web 维护页面、组件、SSR/BFF、浏览器状态、视觉/交互研究、模板评估及展示文案输入。API 维护 HTTP 服务、最终授权、业务规则、事务、Schema、存储、安全执行和运维。跨栈原稿按章节拆分，每个段落只在所属仓库维护正文，另一仓保留引用；共享业务背景及全栈阶段计划由 API 保存并供 Web 引用。

产品基线、业务路线和跨栈历史架构仍由 [API 文档入口](https://github.com/gduf-community/competition-Q-A-website/blob/main/docs/README.md)维护；它们是跨仓约束，不因存在页面描述就整篇迁移。私有安全审计、运维与性能原始数据、实体关系图、通用参考模板留在 API，完整逐文件归属见 [API 迁移清单](https://github.com/gduf-community/competition-Q-A-website/blob/main/docs/文档归属与迁移清单.md)。

原稿引用的临时远程图片地址按原样保留，本次未下载补档或验证外站有效性。图片压缩与懒加载草稿原有引用标签缺少定义，已在稿首标记；不补造来源。Word 的内嵌图片、批注和文档元数据随原文件保留。
